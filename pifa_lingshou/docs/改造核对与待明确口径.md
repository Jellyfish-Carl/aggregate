`problem_solver/l3_spot_storage_milp.py` 已移除。它原来只有兼容导出：把储能 `dispatch` 暴露为 `solve_storage_milp`，把旧的 `solve_l3_milp` 转发到 `l3_milp.py`，没有自己的优化变量或约束。现在兼容别名直接放在 `problem_solver/storage_milp.py`，储能只有一个实现；`l3_milp.py` 继续独立负责日前申报，避免日前申报被储能阶段回写。

前端顺序为创建/编辑输入 → 全预测期套餐推荐 → 人工逐客户确认 → 分阶段采购/储能 → 实绩结算。推荐按负荷稳定性优先，并检查客户节省与公司期望利润。签约前估计用可编辑成本代理，不是未来采购的已知结果。已签条款、已完成节点、已执行前缀不能改写。

案例路径采用实际日历交割天数，将历史合同供给和覆盖考核统一折算到当前节点范围；兼容入口仍保留原月等值口径。两者都采用范围内日均曲线，未扩展成逐日全年联合模型。标的日结算不等同于正式月结。日前和日内储能更新均刷新负荷/实时价格预测区间，日前申报保持锁定。

## 改造结果

原 pifa 的源码在同级目录完整保留。默认批零入口不再调用另一套三场景零售演示求解器，也不再依赖 `simulate()` 一次跑完才能获得中间结果，而是由 `service/layer_runner.py` 调用原批发模块：

1. **签约配置**：`FullModelInput`、客户价格、参考价和套餐在采购之前给定。每个独立链路固定一个风险权重；支持 `customer_packages` 对每个客户分别确定套餐。未指定的客户采用本链路默认套餐。改变已签条款应新开链路，不能改写已成交上游。
2. **L1**：年/月/旬各自调用原48点合同MILP，使用原覆盖考核、代理补救成本等约束；五档场景收入现在进入净损失CVaR。各节点真实返回求解器状态与规模。
3. **L2**：D-3、D-2逐笔撮合保留原规则、仓位控制及部分成交。其现货边际价值由原L3 MILP计算；撮合本身是规则，不冒充MILP。
4. **L3-A**：储能功率置0，原96点现货模型独立形成申报。已成交合同不能改动，申报完成后提供给储能层。
5. **储能**：新增固定申报MILP，日前与日内使用同一目标。96个充放方向二进制，包含SOC上下界、效率、初末SOC、套利现金流、实时偏差回收、合同覆盖考核、退化和CVaR。日内增加实际负荷/价格/充放电/SOC前缀的硬锁定，根据剩余预测重算。

节点输出 JSON 包含输入来源、锁定合同、申报/策略、场景和solver信息。L1、L2、L3-A、储能及各子节点均可使用默认前置值、上游JSON或手动输入运行。无求解器时直接报错，不生成假的最优状态。

## 实时互斥、储能目标与性能

原现货模型的买卖变量具有方向二进制约束，逐场景每时段不允许同时买卖。独立储能层在申报固定后直接用有符号净电量：

`net = 客户负荷 − 固定申报 + 充电 − 放电`，`买入=max(net,0)`，`卖出=max(-net,0)`。

能量现金流、交易摩擦和原有利价差回收构成分段凸函数，用四条线性支持约束精确表示，因此无需再给每个场景添加买卖二进制。储能充放电仍有96个真实二进制，模型是MILP。不同场景下方向可不同，跨场景E[买]和E[卖]同时大于0不代表同场景互斥失效；主图取同一代表场景，统计图展示净交易期望。

默认8条代表场景按无储能净损失分层选择，保留两端，原概率归给最近代表；最终同一策略在原64条场景上全量回算。代表场景目标和原始场景评价目标分别保存，gap只属于前者。此设置支持快速滚动，不能声称已获得64场景最优储能策略；需要时可将优化场景数设为64，并自行配置时限。

默认 `hard_deviation=false`：未来场景的实时偏差按原有利价差公式计费，可能付费越过10%带；**不等同于所有场景无偏差违规**。`hard_deviation=true` 时对全部原始场景的未来时点施加硬约束，即使目标只使用8个代表。若固定申报、实绩、容量或所有场景不能同时满足，模型会明确返回不可行。

低充高放带来的节省通过相同合同、申报和场景的启停储能对照核算；初末SOC不同或禁用储能无法满足硬约束时，显示对照不适用，不编造节省额。

## 成本与客户口径

九项互斥成本：年度、月度、旬内、D-3滚撮、D-2滚撮、日前现货、实时现货、罚款/偏差考核、储能退化。对应交易费用记在该项，现货卖出记负成本；合同合计是小计，不二次加总。

罚款包括实时有利价差回收、年度不足及总体覆盖越界的目标日预测费用。合同罚款按对应半小时归入两个15分钟时段，不再均摊整天；然后按客户时段用电量归集。

按用户指定方法，在每条场景每时段先算公司净采购成本均价和零售收入均价，再乘各客户实际使用的分时电量，最后求和与取场景统计量。客户列中的成本/收入/净收益是公司业务在客户之间的分摊；实际套餐账单另列。客户价差P10–P90来自每条场景的价差分布，不是均价期望相减后人为加减一个区间。

储能充电成本记在充电时段，未构建电量库存向放电时段结转的会计体系。零负荷时段无法定义分摊单价，该时段现金流保留为公司未分摊项，不丢弃。默认场景各时段负荷均大于0。

`visualize.py` 是可视化入口；`storage_validation.py` 仅做启停储能对照。顶部工作台提供入参、默认/上游/手动来源、各节点计算按钮、阶段进度、日志与结果链接。选择上游时继承价格及已签配置，不用页面旧默认值覆盖它。

下方两页：批发页沿用原pifa的96点正负堆叠、年/月/旬层界、日前/实时交易、预测带与悬浮明细，并展示充放电/SOC及价格；收益页展示公司和客户分时归集、九项成本，以及各客户λ–期望价差/P10–P90。

`run_demo` 输出文件地址并尝试启动只监听127.0.0.1的服务。`--no-server` 只生成离线报告。离线可以切换图表，计算必须连接服务。进度表示建模和求解阶段，MILP内部求解时保持当前阶段、更新时间，不伪造实时求解百分比。

## 仍需资料或明确的边界

1. **合同考核计量点**：目前材料没有明确储能是否改变年度和总合同覆盖率的负荷分母。默认 `grid_net_load` 假设储能后并网净负荷参与考核；`customer_load` 则由客户用电量决定，储能不能改变该项罚款。应由适用市场结算条款确认。
2. **月累计结算**：当前合同费用和覆盖回收是按48点折算的目标日预测。原pifa完整月度结算模块保留，但本报告没有伪造月累计逐日实绩；缺这些数据不能输出正式月罚款。
3. **并网边界**：沿用原pifa的20MW参数是申报物理上限，不是所有随机场景的并网净潮流硬约束。独立储能另支持 `grid_import_limit_mwh`、`grid_export_limit_mwh`，按并网协议明确后可对全原始场景未来点限制；默认未提供这两个参数。默认预测尾部可能超过申报功率上限，不能据此认定实际并网合规。
4. **预测与客户数据**：64条原pifa Mock轨迹、客户套餐价格和分时占比仍是演示数据。逐客户真实预测、已执行计量、预测区间历史覆盖率校准尚缺；P10–P90不能声称具有已验证的80%覆盖率。
5. **分层最优性**：L1仍用五档负荷和补救成本代理，虽已加入套餐收入，也没有完整跨节点场景树；L2仍按规则撮合。申报先定、储能后定，是用户要求的顺序决策，不是原联合模型的相同最优解；λ–期望收益与风险宽度不保证单调，不能画成声称全局有效的风险前沿。
6. **客户分摊规则**：当前按公司分时均价分摊，客户套餐账单与分摊收入并不必然相等；如需把储能收益按受益客户而非发生时段归集，需要另定库存、损耗与收益分配规则。
